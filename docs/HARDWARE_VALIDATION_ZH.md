## CI 能证明什么

CI 编译可以证明：

- 依赖能够解析；
- 被测矩阵中的头文件和 API 兼容；
- ESP32-C6 目标及分区配置有效；
- 链接成功；
- 能生成完整的示例烧录包。

## CI 不能证明什么

CI 编译不能证明：

- GPIO、I2C、SPI、I2S、MIPI/DBI 或中断引脚与特定 PCB 修订版一致；
- 显示方向、颜色顺序、时序或亮度正确；
- 触控变换和手势行为正确；
- 麦克风/扬声器路由和模拟性能正确；
- 充电、电池测量或休眠电流正确；
- 射频、存储、散热或电源完整性正确；
- 保留的出厂或 XiaoZhi 恢复镜像适用于具体硬件。

示例配置能证明选择了 16 MB Flash，但没有配置或验证 PSRAM；明确提供选择的示例
使用无 PSRAM 路径。

## 发布证据

发布前，应在硬件上验证每个受影响面，并记录开发板修订版、示例或固件、产物提交、
观察结果和使用的测量设备。修改引脚或外设时序时，应引用精确的原理图修订版及相关
页码或网络。必须明确标记未测试部分，不得把源码层面对比表述为硬件一致性结论。
